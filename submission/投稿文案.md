## 作品简介（100 字内，用于详情页摘要）

iPhone 用户想把 iCloud 里的照片原图导回电脑，通常只有两条路：网页版一张张点，或者啃 icloudpd 那几十个命令行参数。iCloudPD Studio 把后者变成了一个能双击打开的桌面应用——配置同步、实时进度、双重认证、本地图库，都在同一个窗口里。

## 详细介绍（正文）

### 一、为什么做这个

iCloud 是租来的空间。照片在上面，原件却不容易拿下来。

网页版 iCloud 只能一张张点，下下来往往还不是原始画质；官方的「下载原件」要整批走，不能挑选、不能断点续传，中途断了就得从头再来。真要把照片拿回本地，绕不开 `icloudpd` 这个开源命令行工具——它确实能把原图按目录结构完整拉下来，但门槛摆在那儿：

- 得先装 Python，再 pip install，还得让 icloudpd 进 PATH；
- 同步范围、相册、目录结构、尺寸、去重策略，几十个参数散在文档里；
- 第一次登录会触发双重认证，验证码要在终端里手动喂进去；
- 下载中途想看看进度，只能盯着一行行滚动的日志。

我自己就是这个工具的重度用户，也被这套流程劝退过好几次。所以做了这件事：**不动 icloudpd 一行代码，给它补一个界面。**

### 二、它长什么样

一个本地的桌面应用，原生 WebView2 窗口，五个页面：

- **工作台**：本地归档的文件数、占用空间、最近写入时间，一眼看清硬盘上到底存了多少。
- **同步下载**：账户、区域、范围（全部 / 最近 N 个 / 日期区间 / 指定相册）、媒体类型、目录结构、尺寸、XMP、EXIF、去重策略，全部结构化配置，右侧实时生成「运行摘要」告诉你这次到底要跑什么。
- **任务记录**：把 icloudpd 的 stdout 实时接进来，已下载 / 已跳过 / 错误三路计数，外加耗时。
- **照片图库**：扫描下载目录生成缩略图，支持搜索、照片/视频筛选、排序和灯箱预览。HEIC 靠 Pillow + pillow-heif 解码，视频首帧交给 ffmpeg。
- **设置**：存储路径、账户会话、引擎检测、主题切换。

视觉上做了两套主题——暖白纸张和暗房，跟随系统或手动切换。界面全部可在桌面、平板、手机尺寸下使用。

### 三、几个真正花时间的地方

**1. 双重认证的交互**

icloudpd 是独立进程，登录时会在 stdout 里打印提示然后**阻塞等输入**。GUI 里没有终端，用户看不到提示，任务就会一直卡住。

做法是逐段解码子进程输出（icloudpd 官方发行的是冻结二进制，不理睬 `PYTHONIOENCODING`，中文 Windows 上走 cp936/GBK，这里做了多编码试探，避免中文路径变成乱码），匹配到验证码/密码提示就把输入框推到任务面板上，用户填完写回子进程 stdin。识别不到的情况还留了一个「输入」按钮，手动提交兜底。

**2. 只允许一个任务在跑**

两个 icloudpd 进程访问同一个 Apple ID，会话会互相踢掉。所以 UI 层面限制同时只跑一个任务，并且清理进程树时用 `taskkill /T` 连子进程一起收掉，避免留下孤儿进程继续占着会话。

**3. 密码的边界**

密码不写配置、不写日志，只在启动 icloudpd 时留在内存里，作为 `--password` 传给子进程。这一点在 README 里写得很直白——本机其他有权限的进程在任务运行期间能看到该进程参数，介意的话就先通过「登录 / 重验」保存会话，之后留空密码运行。不假装它比实际更安全。

**4. 任意磁盘的目录选择**

浏览器原生的文件夹选择器拿不到盘符列表，选非系统盘要一层层点进去。这里自己实现了目录浏览接口，直接列出 C:/D:/E: 所有磁盘，从根开始浏览。

**5. 破坏性操作要二次确认**

「下载后删除原件」「清空最近删除」「只保留最近 N 天」这三类操作会造成不可逆的后果，一律弹确认框。

### 四、技术实现

- **形态**：Python 标准库 `ThreadingHTTPServer` 提供本地 HTTP 服务，只监听 `127.0.0.1`；`pywebview` 包一层原生 WebView2 窗口，关窗自动停掉自己启动的服务和任务。
- **前端**：零框架，单个 `index.html` + `styles.css` + `app.js`，hash 路由、表单、轮询、灯箱全部手写，没有构建步骤。
- **与引擎的关系**：不做任何下载逻辑的重写，`icloudpd` 仍是唯一的执行者。界面只负责拼参数、起进程、读输出、管输入。上游升级，这边基本不用动。
- **打包**：PyInstaller 打成单文件 exe，`icloudpd` 与 `pillow-heif` 一并内嵌。同一个程序靠参数区分三种身份——开窗、跑本地服务、充当 icloudpd 引擎本体，所以使用者不需要装 Python，也不需要单独装 icloudpd。

### 五、数据与隐私

- 服务只监听本机回环地址，不向局域网暴露。
- 没有账号系统、没有遥测、没有云端中转。
- 配置存在 `data/config.json`，任务日志在 `data/jobs/`，缩略图在 `data/thumbs/`，全在本地。
- iCloud 会话由 icloudpd 保存在 `~/.pyicloud`，等同于账户凭据，不随程序分发。

### 六、已知的边界

- ADP（高级数据保护）账户无法通过 icloudpd 登录，这是上游限制。
- 不做定时任务，需要定期备份可以用系统任务计划程序调用。
- 服务重启后，运行中的任务会标记为「已中断」，不自动恢复；重跑同一配置即可增量续传。

### 七、怎么体验

**下载地址**

https://github.com/Niobium-41-nb/icloudpd-studio/releases/download/v1.0.0/iCloudPD-Studio-1.0.0-win64.zip

解压后双击 `iCloudPD Studio.exe`，**不需要 Python、不需要预装 icloudpd**——下载引擎已经随包放在同一个文件夹里。首次运行会在程序旁边生成 `data/` 目录。

**评审建议的体验路径（约 2 分钟）**

1. 双击打开 → 工作台会显示引擎状态（v1.32.3 已就绪）、本地归档统计、磁盘占用；
2. 进「同步下载」，随便填个场景：选「最近 500 个」、勾「仅预览待下载清单」，右侧「运行摘要」会实时显示将要执行的 icloudpd 命令——**这是最能体现本项目定位的地方：界面只是参数的可视化，真正干活的仍是命令行引擎**；
3. 进「照片图库」看本地目录的缩略图墙、筛选和灯箱；
4. 进「设置」看存储路径、账户会话与引擎检测。

**要真正跑一次同步**，需要你自己的 Apple ID 和一个上游可用的 icloudpd 账号——这是命令行工具本身的登录约束，不是界面加的。没有账号也可以完整浏览界面、配置参数、查看本地目录的图库。

> 截图与演示数据说明：随附的界面截图中，账号一栏为空、目录为演示路径，照片为示例素材，不涉及任何真实账户信息。
